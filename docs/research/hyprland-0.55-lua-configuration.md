# Hyprland 0.55 Lua configuration: facts and migration constraints

Research date: 2026-09-12. Researched version: Hyprland 0.55.0 (released 2026-05-09),
against the version-pinned wiki at https://wiki.hypr.land/0.55.0/ and the Hyprland
news posts. Home Manager facts come from the upstream `home-manager` module source
and are labeled Home Manager, not Hyprland.

## TL;DR

Hyprland 0.55 made Lua the config language. `hyprland.lua` is loaded instead of
`hyprland.conf` when it exists. The old hyprlang syntax is deprecated in 0.55, gets
no new features, and upstream says it will survive only 1 to 2 releases from 0.55
(0.56, shipped 2026-07-20, kept it and had "no breaking changes"). Every config
construct this repo uses today (monitors, binds, window rules, workspace rules,
dwindle options, colors, env vars, autostart) has a documented Lua equivalent, but
the shapes change from comma-separated strings to Lua tables and `hl.*` calls. Home
Manager already renders `wayland.windowManager.hyprland.settings` to Lua when
`configType = "lua"`, so the migration can stay declarative, but our current
`settings` keys (hyprlang-style strings like `exec-once` and `workspace`) do not map
1:1 and need rework.

## Exact facts (Hyprland 0.55)

### File, loading, reload, errors

- The config lives at `$XDG_CONFIG_HOME/hypr/hyprland.lua`, usually
  `~/.config/hypr/hyprland.lua`. `hyprland -c` / `--config` selects another file.
  The `HYPRLAND_CONFIG` env var also points at a config file. (Start, Environment-variables)
- If no `hyprland.lua` exists, Hyprland generates an example config with a
  `hl.config({ autogenerated = true })` line; removing that line removes a yellow
  warning. (Start)
- Lua wins over hyprlang: "if you do have one, `hyprland.lua` will be loaded
  instead" of `hyprland.conf`. The check happens once at startup only. (news/26_lua)
- The config reloads the moment you save it; `hyprctl reload` forces a reload. (Start)
- Error behavior, four tiers (Start):
  - Lua syntax errors: Hyprland refuses to reload and shows an error.
  - Runtime Lua errors (e.g. calling a nil): the current Lua file aborts and an
    error pops. Anything after the error in that file does not load.
  - Hyprland type errors in `hl.*` calls (e.g. string where a float is wanted):
    execution continues, error pops.
  - Errors inside async code (e.g. a bind function) pop a notification.
- `require()` loads other files, and each required file runs as its own Lua scope,
  so an error in one required file does not stop the others. Recommended layout.
  (Start)
- If a fatal error happens before the binds on startup, Hyprland grants emergency
  binds: `SUPER+Q` (terminal), `SUPER+R` (run), `SUPER+M` (exit), and says so in the
  error popup. (Start)
- Infinite loops and re-entrant event scripts are killed after a timeout or limit.
  The Lua standard libraries are loaded by default. (Start)
- Editor support: autogenerated Lua stubs ship in the Hyprland repo `meta/`
  directory, installed to `/usr/share/hypr/stubs/`. Point a Lua LSP there and add
  `hl` to diagnostics globals. (Start). Home Manager also generates a
  `.luarc.json` when `configType = "lua"` (Home Manager module source).

### Options: hl.config

- Options are set with nested tables: `hl.config({ general = { gaps_in = 3 },
  input = { kb_layout = "us,cz" } })`. Categories match the hyprlang section names
  (`general`, `input`, `binds`, `xwayland`, `render`, `cursor`, `misc`, `debug`,
  `dwindle`, `master`, `decoration`, ...). Layout pages confirm: dwindle is
  `category name: dwindle`; master is `hl.config({ master = {...} })`.
  (Variables, Binds, Dwindle-Layout, Master-Layout)
- `hl.config()` can be called again later (e.g. from a bind) to change options at
  runtime. (Expanding-functionality)
- Read an option with `hl.get_config("general.gaps_in")`. The return value has the
  underlying type shape: `gaps_in = 3` returns `{ top = 3, left = 3, right = 3,
  bottom = 3 }`. (Expanding-functionality)
- Hyprlang variables do not exist. Use plain Lua locals and string concatenation:
  `hl.bind(mainMod .. " + K", ...)`. (Binds)
- Variable types map to Lua directly: int, bool, float, str, vec2 as `{ 20, 20 }`,
  `css_gaps` as an integer or `{ top?, left?, right?, bottom? }`, gradient as a
  color or `{ colors = { "rgba(...)", ... }, angle? = 45 }`. (Variables)
- Colors accept: `#fafc21` / `#fa3d7bff` (rgba order), `rgba(b3ff1aee)` or decimal
  `rgba(179,255,26,0.933)`, `rgb(b3ff1a)` / decimal `rgb(179,255,26)`, and legacy
  `0xeeb3ff1a` (ARGB). (Variables). Our Catppuccin hex values can be used as
  `rgb(...)` strings or in gradient tables; the `theme.nix` helper still works.
- Gaps note: `general.gaps_out` is a `css_gaps` value now. Our current
  `gaps_out = "10,18,18,18"` string must become a table like
  `{ top = 10, left = 18, right = 18, bottom = 18 }`. (Variables, css_gaps type)
- Environment variables: `hl.env("GTK_THEME", "Nord")` sets them before the display
  server initializes. All our `env.nix` vars (GDK_BACKEND, QT_*, XDG_*, XCURSOR_*)
  are documented as `hl.env(...)` calls on the 0.55 page. (Environment-variables)

### Monitors

- `hl.monitor({ output = "DP-1", mode = "1920x1080@144", position = "0x0",
  scale = 1 })`. Fields beyond `output` are optional. (Monitors)
- Field list: `output`, `mode`, `position`, `scale`, `disabled`, `transform` (0-7),
  `mirror`, `bitdepth` (8 or 10), `cm` (color preset), `sdr_eotf`, `sdrbrightness`,
  `sdrsaturation`, `vrr`, `icc` (absolute path), `reserved_area` (int or table
  `{ top, bottom, left, right }`), plus HDR luminance fields. (Monitors)
- Special modes: `preferred`, `highres`, `highrr`, `maxwidth`; positions `auto`,
  `auto-right/left/up/down`, `auto-center-*`; `scale = "auto"`. A rule with an empty
  `output` is the fallback for unplugged monitors. `desc:` prefixes work on the
  output description. (Monitors)
- `hl.monitor({ output = "name", disabled = true })` removes a monitor from the
  layout; the `dpms` dispatcher is the screensaver-style off. (Monitors)
- Our `dotfiles.hyprland.monitors` strings ("DP-1, 5120x1440@119.98Hz, auto, auto,
  bitdepth, 8, cm, auto") must be re-shaped into Lua field tables during migration;
  `bitdepth = 8, cm = "auto"` becomes `bitdepth = 8, cm = "auto"` fields.

### Binds

- `hl.bind("SUPER + SHIFT + Q", hl.dsp.exec_cmd("firefox"))`. Keys without a modkey
  just omit it: `hl.bind("Print", ...)`. (Binds)
- The dispatcher argument can be a Lua function; call dispatchers inside it with
  `hl.dispatch(hl.dsp....)`. Multiple actions per bind run top to bottom in order.
  (Binds)
- Flags go in a third table: `hl.bind(keys, dispatcher, { release = true,
  locked = true, repeating = true, long_press = true, mouse = true,
  submap_universal = true, description = "...", devices = { inclusive = true,
  list = { "..." } }, ... })`. Full flag list: locked, release, click, drag,
  long_press, repeating, non_consuming, auto_consuming, mouse, transparent,
  ignore_mods, separate, description, bypass, submap_universal, devices. (Binds)
- Mouse: `mouse:272` (LMB), `mouse:273` (RMB), `mouse_down`/`mouse_up` for wheel;
  mouse binds use `hl.dsp.window.drag()` / `hl.dsp.window.resize()` with the
  `mouse = true` flag. `binds:drag_threshold` separates click from drag. (Binds)
- Keycodes: `code:28` prefix. Keysym names are the segment after `XKB_KEY_` in
  xkbcommon-keysyms.h. `wev` helps find names. (Binds)
- Submaps: `hl.bind("ALT + R", hl.dsp.submap("resize"))` then
  `hl.define_submap("resize", function() ... end)` with binds inside; nested
  submaps work; `catchall` matches any key; `hl.dsp.submap("reset")` exits;
  submaps can auto-advance by naming a follow-up submap or `reset`. (Binds)
- Unbind: `hl.unbind("SUPER + O")`; the key string is case-sensitive and must
  match the bind exactly. (Binds)
- Global keybinds: `hl.dsp.pass({ window = "class:..." })` and
  `hl.dsp.send_shortcut({ mods = "SUPER", key = "F4", window = "class:..." })`;
  DBus global shortcuts via `hl.dsp.global("coolApp:myToggle")`. (Binds)
- Per-device binds take the `devices` flag with `inclusive` and a `list`. Device
  tags come from `hl.device()` (Devices page). (Binds, Devices)

### Dispatchers

- Dispatchers build tables that describe an action; they do nothing until fed to
  `hl.bind()` or `hl.dispatch()`. (Dispatchers)
- Namespaced under `hl.dsp.`: general (`exec_cmd(cmd, rules?)`, `exec_raw(cmd)`,
  `focus({ direction | monitor | workspace | window | urgent_or_last | last })`,
  `exit()`, `submap(name)`, `pass`, `send_shortcut`, `send_key_state`, `layout`,
  `dpms`, `event`, `global`, `force_idle`, `no_op`), plus groups `hl.dsp.window.`
  (`close`, `kill`, `float`, `tag`, ...) and workspace/window move/resize groups.
  (Dispatchers, Window-Rules)
- Window params: window object, regex selectors `class:`, `initialclass:`,
  `title:`, `initialtitle:`, `tag:`, exact selectors `pid:`, `address:0x`,
  `activewindow`, `floating`, `tiled`; default is the active window. Workspace
  params: object, ID, or selector. Monitor params: object, ID, direction, name,
  `desc:`, `current`, `relative:+1/-2`. (Dispatchers)
- `hl.dsp.exec_cmd()` runs through `bash -c` asynchronously, so no `&` disown is
  needed. (Autostart, Dispatchers)

### Window and layer rules

- `hl.window_rule({ name = "apply-something", match = { class = "my-window" },
  border_size = 10 })`. Named rules are optional; without `name` the rule is
  anonymous. `match` fields are props (all must match); the remaining fields are
  effects. At least one prop is required; each prop type may appear once. (Window-Rules)
- Props: `class`, `title`, `initial_class`, `initial_title` (RegEx), `tag`,
  `xwayland`, `float`, `fullscreen`, `pin`, `focus`, `group`, `modal`,
  `fullscreen_state_client`, `fullscreen_state_internal`, `workspace`, `content`,
  `xdg_tag`. (Window-Rules)
- Regex is Google RE2; no polynomial-time patterns. Negate with a `negative:`
  prefix. (Window-Rules)
- Static effects apply once at window open (and match against initialTitle /
  initialClass): `float`, `tile`, `fullscreen`, `maximize`, `fullscreen_state`,
  `move`, `size`, `center`, `pseudo`, `monitor`, `workspace`, `no_initial_focus`,
  `pin`, `group`, `suppress_event`, `content`, `no_close_for`, `scrolling_width`.
  (Window-Rules)
- Dynamic effects re-evaluate when properties change: `persistent_size`,
  `no_max_size`, `stay_focused`, `animation`, `border_color`, `idle_inhibit`
  ("none", "always", "focus", "fullscreen"), `opacity`, `tag`, `max_size`,
  `min_size`, `border_size`, `rounding`, `rounding_power`, `allows_input`,
  `dim_around`, `decorate`, `focus_on_activate`, `keep_aspect_ratio`,
  `nearest_neighbor`, `no_anim`, `no_blur`, `no_dim`, `no_focus`, `no_follow_mouse`,
  `no_shadow`, `no_shortcuts_inhibit`, `no_screen_share`, `no_vrr`, `opaque`,
  `force_rgbx`, `sync_fullscreen`, `immediate`, `xray`, `render_unfocused`,
  `scroll_mouse`, `scroll_touchpad`, `confine_pointer`. (Window-Rules)
- Precedence: effects process top to bottom, last match wins. All named rules
  evaluate first, then anonymous ones. (Window-Rules)
- Named rules return a handle: `myRule:set_enabled(false)`, `is_enabled()`.
  Only named rules can change dynamically. (Window-Rules)
- Layer rules: `hl.layer_rule({ match = { namespace = "waybar" }, blur = true })`,
  same syntax; effects include `blur`, `blur_popups`, `ignore_alpha`, `dim_around`,
  `xray`, `animation`, `order`, `above_lock`, `no_anim`, `no_screen_share`.
  (Window-Rules)
- Our current hyprlang windowrule strings (float by class/title, size 1024x768,
  border_size 0 fullscreen, idle_inhibit fullscreen, suppress maximize) map to
  separate `hl.window_rule` tables: float rules use `float = true, center = true,
  size = {...}` effects; note the docs show `size` taking a string or expression
  table and there is no dedicated example of our exact "float + size + center"
  combo (see unknowns).

### Workspace rules

- `hl.workspace_rule({ workspace = "name:coding", monitor = "DP-1",
  default = true, gaps_in = 0, ... })`. One table holds the workspace identifier
  plus rules. (Workspace-Rules)
- Rules: `monitor`, `default`, `gaps_in`, `gaps_out`, `border_size`, `no_border`,
  `no_shadow`, `no_rounding`, `decorate`, `persistent`, `on_created_empty`,
  `default_name`, `layout`, `animation`. (Workspace-Rules)
- Our persistent workspaces 1-5 become five calls:
  `hl.workspace_rule({ workspace = "1", persistent = true })` and so on.
  (Workspace-Rules)

### Autostart and events

- Autostart runs on the `hyprland.start` event:
  `hl.on("hyprland.start", function() hl.exec_cmd(terminal) ... end)`. Exit tasks
  use `hyprland.shutdown`. `hl.exec_cmd()` is asynchronous. (Autostart)
- `hl.on` registers event callbacks; the documented event list includes
  `hyprland.start`, `hyprland.shutdown`, `window.open`, `window.open_early`,
  `window.close`, `window.destroy`, `window.active`, `workspace.active`,
  `monitor.added`, `monitor.focused`, `config.reloaded`, `keybinds.submap`,
  `screenshare.state`, and more. (Expanding-functionality)
- Convenience getters: `hl.get_config()`, `hl.get_active_window()`,
  `hl.get_windows()`, `hl.get_workspaces()`, `hl.get_monitors()`,
  `hl.get_active_monitor()`, `hl.get_current_submap()`, `hl.version()`, etc.
  (Expanding-functionality)
- Timers: `hl.timer(function() ... end, { timeout = 1000, type = "repeat" })` with
  `:set_enabled()` / `:is_enabled()`. (Expanding-functionality)
- For IPC consumers, upstream recommends Lua over sockets ("faster, less buggy,
  more APIs, more integrated"). (Expanding-functionality)

### Animations

- `hl.animation({ leaf = "workspaces", enabled = true, speed = 8,
  bezier = "my_epic_bezier" })` plus `hl.curve(NAME, { type = "bezier",
  points = { {X0, Y0}, {X1, Y1} } })`. `speed` is in deciseconds (1 = 100ms).
  Animations form a tree and inherit unset values. (Animations)

### Devices

- Per-device config: `hl.device({ name = "my-epic-keyboard", sensitivity = -0.5 })`.
  All `input` category options are allowed except `force_no_accel` and window
  management options. Extra per-device fields: `enabled`, `keybinds`, `tags`.
  Device names come from `hyprctl devices`. (Devices)

### Plugins

- Unchanged loading model: plugins are `.so` files managed by `hyprpm`
  (`hyprpm add/list/enable/disable/reload/update`) or `hyprctl plugin load`.
  (Using-Plugins)
- Plugin options in Lua: guard with `if hl.plugin.NAME ~= nil`, then call
  `hl.plugin.NAME.func(...)` and set options via
  `hl.config({ plugin = { NAME = { ... } } })`. (Using-Plugins)
- Permission management still exists:
  `permission = /usr/(bin|local/bin)/hyprpm, plugin, allow`. (Using-Plugins)

### hyprctl in 0.55

- `hyprctl eval 'hl.dispatch(hl.dsp.focus({ workspace = "3" }))'` runs a Lua
  string. `hyprctl dispatch 'hl.dsp.focus({ workspace = "3" })'` is shorthand.
  Old-style dispatcher strings are gone from the docs. (Using-hyprctl)
- `hyprctl reload` forces a config reload; `hyprctl configerrors` lists parsing
  errors; `hyprctl getoption general.border_size` keeps the dotted option path;
  `hyprctl descriptions` returns JSON of all options with types. `hyprctl binds`
  shows registered binds including descriptions. (Using-hyprctl, Start)
- Consequence for our helper scripts: `set-screen-share-resolution` /
  `unset-screen-share-resolution` and any `hyprctl dispatch` / `hyprctl keyword`
  calls in scripts must be rewritten to `hyprctl dispatch 'hl.dsp...'` or
  `hyprctl eval '...'` (exact `keyword` replacement not documented, see unknowns).

### Deprecation timeline

- "The old hyprlang syntax will continue to be supported for 1 - 2 releases
  starting from 0.55. After that, hyprlang will be dropped." Also: "New config
  features will also not be added to hyprlang anymore." (news/26_lua)
- 0.55 released 2026-05-09; 0.56 released 2026-07-20 with "no breaking changes"
  and more Lua APIs (REPL mode in hyprctl, new windowrule effects, plugin
  introspection). (news/update55, news/update56)
- Other hypr* tools (hypridle, hyprlock, hyprpaper, hyprlock...) keep hyprlang
  configs for now; only Hyprland itself moved to Lua. (news/26_lua)

## Home Manager behavior (not Hyprland)

These facts are about the Home Manager module
(`wayland.windowManager.hyprland.*`), version `master` as of 2026-09 (they may not
exist in the HM revision pinned by this flake; that must be checked before
migrating).

- `configType` option: enum `"hyprlang"` or `"lua"`. Default comes from
  `home.stateVersion`: state versions older than 26.05 default to `"hyprlang"`,
  newer ones to `"lua"` (via `lib.hm.deprecations.mkStateVersionOptionDefault`).
  `hyprlang` writes `hypr/hyprland.conf`; `lua` writes `hypr/hyprland.lua`.
- In `"lua"` mode, `settings` attributes map to `hl.<name>(...)` calls; a list
  value generates one call per element. Special shapes: an `_args` list generates a
  multi-argument call; `_var` generates a Lua local variable instead of a call
  (with optional `name`); `lib.generators.mkLuaInline` renders raw Lua
  expressions.
- `extraConfig` (lines) is appended to the generated file; the module's own
  example is Lua (`hl.on("window.open", ...)`).
- `extraLuaFiles` writes extra `.lua` files under `hypr/`, with attribute names as
  Lua module names (`bindings` becomes `hypr/bindings.lua`,
  `lib.helpers` becomes `hypr/lib/helpers.lua`). Files with `autoLoad = true`
  (default) get a `require(...)` call in the generated `hyprland.lua`, after the
  module adds the config dir to Lua's `package.path`. `autoLoad = false` is for
  helper modules required by other files. A file named `hyprland.lua` cannot be
  defined there (the module owns it).
- The module generates `hypr/.luarc.json` when `configType = "lua"`.
- A news entry dated 2026-05-14 in HM documents `extraLuaFiles`.
- This repo today (modules/home-manager/hyprland/settings.nix:16-20): sets
  `configType = "hyprlang"` explicitly, with a comment that the compositor is held
  at 0.55.4 for hyprlang and that a stray `hyprland.lua` would win over
  `hyprland.conf`. Hosts use `home.stateVersion = "24.05"`, so the stateVersion
  default would also be `"hyprlang"`. The HM module still renders the existing
  `settings` (hyprlang strings like `exec-once` and `workspace` lists) fine in
  `"hyprlang"` mode.

## Migration constraints for this repo

1. One language at a time. `hyprland.lua` beats `hyprland.conf` at startup. The
   migration must land HM `configType = "lua"` and all Lua content in the same
   change, then delete the hyprlang-era `settings` keys.
2. `settings` keys do not transfer. In HM Lua mode each attribute becomes an
   `hl.<name>(...)` call. Our keys `exec-once` and `workspace` are hyprlang
   constructs with no `hl.exec_once` / string-rule equivalent; they must be
   re-expressed as `extraConfig` Lua (`hl.on("hyprland.start", ...)` and
   `hl.workspace_rule(...)`) or `extraLuaFiles` modules.
3. Monitor specs need re-shaping. `dotfiles.hyprland.monitors` is a list of
   hyprlang monitor strings. The Lua target is `hl.monitor({ output, mode,
   position, scale, bitdepth, cm, ... })` tables. The option's type and the host
   values in `hosts/nixos-desktop/home.nix` need a new schema, or the strings need
   parsing at eval time.
4. String-typed values become typed values. `gaps_out = "10,18,18,18"` becomes a
   `css_gaps` table; `single_window_aspect_ratio = "16 9"` stays a string (Vec2D
   hint shows `{ 20, 20 }` style for vec2; check which the layout page wants);
   `force_split = 2` and `preserve_split = true` are already typed and transfer
   into `hl.config({ dwindle = {...} })`.
5. Binds move from `bind =` string lists to `hl.bind(...)` calls. Our bindings
   (SUPER-based, workspace 1-9, tab cycling, mouse drag with SHIFT+ALT) map
   directly, but need `mainMod .. " + X"` Lua expressions or HM `_var` locals
   instead of hyprlang `$mod` variables.
6. Window rules need full rewrite. The old `windowrulev2` strings become
   `hl.window_rule` tables with `match` and effects; order still matters (last
   match wins); the floating-class list can be generated as many anonymous rules
   or one rule per class.
7. Theme colors survive. `rgb(...)` strings and gradients (`{ colors = {...},
   angle = 45 }`) are first-class in 0.55, so `theme.nix` needs only minor output
   shaping.
8. hyprctl-based scripts must move to Lua expressions. Anything calling
   `hyprctl dispatch <legacy string>` or `hyprctl keyword` breaks. Rewrite as
   `hyprctl dispatch 'hl.dsp...'` / `hyprctl eval '...'`.
9. Companion tools keep hyprlang. `hypridle.conf`, `hyprlock.conf`,
   `hyprpaper.conf` do not migrate to Lua in 0.55; our sibling modules stay as
   they are.
10. HM version gate. The `configType` / `extraLuaFiles` options exist on HM
    master (2026). Verify the HM revision this flake pins has them; if not, the
    migration needs an HM bump first.
11. Deprecation clock. hyprlang gets no new features and dies 1-2 releases after
    0.55. The current hold at 0.55.4 for hyprlang is a temporary Channel-Hold-style
    state; the exit condition is this migration (or 0.56+, which still loads
    hyprlang but is the last safe stop).

## Unknowns

- Which HM release first shipped `configType` and `extraLuaFiles` (found on
  master; pin not checked). Must verify the flake's HM input before planning.
- Exact HM rendering of `exec-once`-style keys in `"lua"` mode: does
  `settings.exec-once = [...]` produce a call at all, or error? No documentation
  covers keys without an `hl.*` counterpart.
- Whether `hyprctl keyword` still exists in 0.55 or was replaced by
  `hyprctl eval 'hl.config({...})'` (not stated on the Using-hyprctl page; keyword
  is absent from the documented command list).
- Whether the old-style `hyprctl dispatch "workspace, 3"` strings still parse in
  0.55 alongside the Lua form (docs show only the Lua form).
- The exact `size` effect shape for our floating-rule combo (float + center +
  1024x768 size): docs show `size` as a string or expression pair, no composed
  example; needs a live test on 0.55.
- Whether `hl.animation` uses `bezier = ...` or `spring = ...` strictly (examples
  show both; the doc text says "bezier / spring is the curve name").
- When hyprlang is actually dropped (0.57?), and whether the drop also removes
  the `hyprland.conf` fallback or just warns.
- Home Manager behavior for `submaps`: HM has a `submaps` option (referenced in
  its assertions), but its Lua-mode semantics were not examined here.

## Decision implications

- The migration is real and unavoidable upstream; the only question is timing. If
  we stay on hyprlang, we must hold Hyprland and accept no new config features.
- The clean migration path in this repo is: bump HM to a revision with
  `configType`, keep `dotfiles.hyprland.monitors` as structured Nix data (attrsets,
  not strings), render `settings` for options that map to `hl.config` categories,
  and put binds, window rules, workspace rules, and autostart into
  `extraLuaFiles` modules (bindings, windowrules, autostart) so they stay editable
  Lua files per ADR-0005's Config Directory pattern.
- A `config/hypr/` Config Directory with hand-written Lua modules required by a
  thin generated `hyprland.lua` is a viable alternative that moves us fully onto
  the native language and out of HM rendering for binds and rules.
